# PocketAgent 批量研究与滚动验证

更新日期：2026-11-07。P2 已加入有限参数挖掘、滚动验证和 FIFO 成交报告，继续使用 P1 的 CPU 账户与执行器。基础安装没有 PyTorch，原行情、模型和训练资产保留。

## 页面操作

启动方式沿用 [CPU 使用说明](CPU_RESEARCH_GUIDE.zh-CN.md)。在“研究方式”中选择单次回测、批量参数挖掘或滚动验证。

批量模式下，每个参数填写以逗号分隔的候选值。例如快均线 `3, 5`，慢均线 `15, 20` 会生成 4 个组合。研究区间和执行费用固定，全部组合共用同一份只读输入。成功与失败尝试均登记，失败组合不会被静默丢弃。

当前有三个可解释策略家族：均线趋势、收盘突破、均值回归；现金和买入持有用于对照。这些策略是研究候选，不预设有效性。

结果页显示样本内排序、每组参数收益和回撤，并可按需读取候选的成交、净值和 FIFO 报告。排名首位仅表示在该研究区间和目标指标上得分最高，不表示通过后续区间验证。

## 笔记本预算

默认一次只运行一个网页研究任务，内部使用一个 CPU worker 串行执行。默认预算：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `max_candidates` | 64 | 去重后参数组合数量上限 |
| `max_backtests` | 512 | 候选训练、验证和 baseline 的回测次数预算 |
| `max_bar_evaluations` | 2000000 | 含 warmup 在内的估计行情处理量预算 |

超限会明确拒绝，不抽样、不截断参数列表。CLI 可在程序硬上限内显式调整预算；这不是运行时间保证，长序列策略的计算量仍受窗口和实现影响。

数据只加载一次。每个候选完成后立即保存完整报告，批次摘要只保留指标和文件引用；baseline 共享，页面点“查看”才读取对应报告。滚动训练候选也不把所有净值和成交曲线同时留在内存。

可以取消运行，已完成试验和结果会保留；下次不会自动把已取消的试验覆盖或当成成功。进度、失败和中断状态落盘，退出进程不会丢掉已经保存的报告。当前尚未提供跨机器任务分发或断点续算。

## 滚动验证的时间规则

默认配置为训练 40 根日线、隔离 1 根、验证 15 根，最后保留 15 根日线作为最终测试段。窗口按输入数据的有效日线条数计算，展示实际起止日期，不自动补齐缺失的交易日。

每折按以下流程执行：

1. 仅在该折过去的训练窗口运行全部候选，按训练指标选出参数。
2. 训练与验证之间保留 gap。gap 行情不进入训练收益评分。
3. 在后续、不重叠的验证窗口运行已选参数，并执行同费用、同资金、同规则的 baseline。
4. 向前移动一个验证窗口，重复选择与验证。可选固定长度或扩展训练窗口。

指标平分时按稳定 candidate ID 决定顺序，保证重复运行结果一致。无效参数作为失败试验记录；如果某折没有有效候选，该折不伪造验证结果。

warmup 只使用验证开始前已知的历史收盘数据，包括 gap。它不成交、不计收益；最后一个 warmup 收盘可以产生首个验证日开盘的委托。当前规则在收盘生成信号、下一开盘执行，每个窗口的初始资金相同。

每折使用独立现金账户。报告中的平均收益、中位数、正收益比例和相对基准胜率，是独立窗口的分布统计；不能把它们当成连续交易组合的真实累计收益。开发区间尾部不足一个完整验证窗口时不计分，数量记录在 `plan.unused_development_bars`。

## 最终测试段

默认 `evaluate_holdout=false`，最终保留段不计算收益或排名。只有显式勾选“本次评估冻结参数的最终测试段”，或在 JSON 中设为 true，才会评估。

最终测试使用此前 calibration 窗口选出的参数；测试段自身不参与选参。它单独保存，页面默认显示最后一个验证窗口，不把最终测试混进开发阶段排名。修改最终测试数据不会改变此前 fold 的选择和验证结果，已用扰动测试核对。

反复查看最终测试结果后再修改策略，会使它失去未见测试的意义。每次使用都留在配置和实验记录中；程序不声称重复评估后仍是未见数据。输入快照与数据校验可能覆盖整段行情，“保留”指不参与收益评价或参数选择，而非不读取原始文件。

## FIFO 报告口径

FIFO 按先进先出匹配实际成交，买卖费用按匹配股数分摊。它是研究报告口径，不改变账户原有平均成本盈亏。

| 报告 | 统计单位 |
| --- | --- |
| `closed_trades` | 一段买入 lot 与一笔卖出 fill 的匹配片段 |
| `sell_orders` | 按 symbol 与 order ID 聚合；无 order ID 时用 signal ID，再退到 fill ID |
| `round_trips` | 仓位从零变为正、再归零的完整轮次 |
| `open_lots` | 期末仍持有的批次、剩余买入费用与未实现盈亏 |

这三种已实现统计分别有自己的次数和胜率，不能混称“交易胜率”。未平仓不计入已实现胜率，也不强制平仓。没有亏损片段时 profit factor 为 null，而非无限大或零；无已平仓记录的胜率同样为 null。

报告保留买入／卖出 ID、成交时刻、股数、价格、买卖费用、净盈亏和持有天数，并核对“已分摊费用 + 未平仓买入费用 = 输入总费用”。拒单独立统计，重复成交 ID、卖出超过已知买入数量、非法价格和费用等明确报错。

独立 API `build_fifo_report` 支持显式期初 lots；导出的 `open_lots` 可作为下一报告期初始库存，保留剩余费用。期初库存的完整轮次会单独标记。当前滚动引擎仍按独立现金账户运行，不把某折期末仓位偷偷带入下一折。

## 命令行与文件

在项目目录运行示例：

```powershell
.\.venv\Scripts\python.exe -m research_layer.cli.run --config docs/examples/research-batch-demo.json --output runtime_layer/reports/research
.\.venv\Scripts\python.exe -m research_layer.cli.run --config docs/examples/research-walkforward-demo.json --output runtime_layer/reports/research
```

示例配置：[批量演示](examples/research-batch-demo.json)、[滚动验证演示](examples/research-walkforward-demo.json)。改为真实数据时设置 `source_type` 为 `market` 或 `csv`，指定 `source_path`、股票及日期区间。窗口和预算字段保持相同。

每个唯一 run 目录包括配置、源码／数据 SHA-256、`input.csv`、`plan.json`、结果与状态。批次增加 `trials.jsonl` 和 `trials.csv`；各候选的完整结果位于其 `artifact_path`。滚动训练报告按 fold 和 candidate 区分，验证报告位于 `folds/<fold_id>/validation/`，最终测试单独保存。

FIFO 随候选、验证和 baseline 输出 JSON、`fifo_closed.csv` 和 `fifo_open.csv`。取消或失败保留 `partial_result.json`，不覆盖其他 run。网页的历史列表目前展示网页创建的任务；CLI 报告按其输出目录读取。

API 增加：

- `POST /api/research/preview`：检查配置和候选规模；未读数据时不伪造数据相关预算。
- `POST /api/research/runs/<job_id>/cancel`：取消当前实例持有的任务。
- `GET /api/research/runs/<job_id>/trials/<candidate_id>`：按需获取批量候选报告；滚动训练候选通过保存的 fold 文件查阅。
