# 周线入场与退出：本地100股独立研究

研究日期：2026-11-14。问题、股票池、参数、四组案例和评价日期在运行前冻结，见 [协议](WEEKLY_COMPONENT_PROTOCOL.zh-CN.md)。这项研究接续云端交付提供的方法与代码，但实际行情来自本地原100只A股前复权数据，不是美股复算。

## 主要发现

原先的 `drop_weekly` 同时取消周线入场和周线退出，不能据此将全部差异归功于“入场方向过滤”。拆开之后，周线退出在两期均降低回撤，但收益效果随区间变化；保留原周线退出时，入场方向过滤在两期都提高平均收益。两个功能存在交互，不能把差值相加或宣称某组件无条件有效。

默认策略和参数保持不变。本次是回顾性机制研究，不按2025表现选赢家。

## 同期限逐股分布

## 配对比较与交互

所有配对均核验同股票、成本、实际日期、行情与日历SHA256。下面是“修改版减原版”的平均收益差，单位为百分点。

| 比较 | 2022–2024的98股 | 2025的100股 |
|---|---:|---:|
| 仅移除入场 − 原版 | -11.155 | -1.002 |
| 仅移除退出 − 原版 | -2.351 | +10.833 |
| 两者均移除 − 原版 | -6.588 | +16.032 |
| 已移除退出时，再移除入场 | -4.237 | +5.199 |

因此“入场过滤两期都有帮助”必须限定为保留原周线退出的情况。2025在没有周线退出时，去掉入场过滤反而提高平均收益。开发区间仅移除退出后只有32.65%股票优于原版；2025该比例为61.00%，也不是每只股票都改善。

## 入场日触止损与T+1

原CN规则把入场日触止损的交易统一标 `ambiguous_intraday_order`，并锁存至下一可交易开盘退出。这个标签也包括开盘入场，因此应称为“引擎标记的入场日触止损/T+1组”，不能全部称真正日内路径歧义。原有执行与标记逻辑未改。

| 原版分组 | 2022–2024的98股 | 2025的100股 |
|---|---:|---:|
| 总入场笔数 | 2,818 | 873 |
| 入场日触止损组：已平仓／未平仓 | 910 / 0 | 218 / 4 |
| 上述已平仓：盘中突破／开盘入场 | 860 / 50 | 212 / 6 |
| 上述已平仓：均笔净收益 | -0.875% | -0.681% |
| 上述已平仓：胜率 | 27.91% | 30.73% |
| 普通组：已平仓／未平仓 | 1,897 / 11 | 628 / 23 |
| 普通组已平仓：均笔净收益 | +0.477% | +1.852% |
| 普通组已平仓：胜率 | 24.14% | 29.30% |

真正涉及盘中突破和日低先后不明的已平仓子组，均笔净收益分别为-0.742%与-0.588%。止损组胜率略高却平均亏损，不能仅按胜率判断质量。以上是成交后的描述统计，不是可提前识别并剔除的信号；单笔均值不是组合收益贡献，未将单笔收益相加为总净值。

## 结果位置和复现

最终源码研究目录：

- `runtime_layer/reports/bundle_research/final_development/study_20261114_125046_5030ec93`
- `runtime_layer/reports/bundle_research/final_validation/study_20261114_125046_032c2822`
- 汇总：`runtime_layer/reports/bundle_research/final_weekly_component_analysis.json`

在已有数据和依赖的环境运行，无网络请求：

```text
python -m research_layer.triple_study --config plans/triple_screen/weekly_component_development.json --cases plans/triple_screen/weekly_component_cases.json --output runtime_layer/reports/weekly_components/development
python -m research_layer.triple_study --config plans/triple_screen/weekly_component_validation.json --cases plans/triple_screen/weekly_component_cases.json --output runtime_layer/reports/weekly_components/validation
python plans/triple_screen/analyze_weekly_components.py --development <development-study-dir> --validation <validation-study-dir> --original runtime_layer/reports/triple_screen/triple_20261112_101445_a783cd4e --output runtime_layer/reports/weekly_components/analysis.json
```

分析脚本逐层核验工件哈希，严格配对，并与本机旧原版逐股比较。Git只保存协议、配置、分析脚本和本摘要；原始行情与运行工件保留本机。

最终两区间各400/400完成、零失败；每区间递归核验2,027个工件引用，共4,054个。最终版原策略100股与旧开发基线的日期、输入哈希、指标、净值、成交、交易一致；信号与决策原字段一致，仅允许后来增加的研究标签字段。收盘字段修复前后两轮的800份完整result对象逐份对照，结果一致。证据分别为 `final_weekly_component_analysis.json` 和 `final_rerun_comparison.json`。

## 下一研究问题

下一步更有价值的是在预先固定的多个年度里重复这套四组对照，检验收益／回撤关系与行情方向是否稳定；随后再研究周线转弱的退出延迟或其他退出方式，而不是直接把2025表现较好的版本替换原版。若研究日内触发顺序，只能增加明确的执行上下界，或以后由用户补充分钟数据；不从日线猜出不存在的成交路径。

固定事后股票池、前复权历史版本、未模拟涨跌停成交限制／手数／真实费用，以及未触碰测试集缺失，仍限制外推。本研究没有做统计显著性声明，也未验证实际投资收益。
